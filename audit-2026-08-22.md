# Audit — 2026-08-22

First full audit of the implementation. Static analysis, a real-browser pass at
1440×900 and 390×844, a production build, and an import-graph walk.

**Baseline going in:** `npm run lint` **failed** (6 errors). **Baseline going
out:** lint, typecheck and build all clean, 0 console errors.

Method matters for the numbers below: bundle sizes are gzipped from a
**production** build (`next build`), not the dev server, whose figures are
inflated by HMR. Reachability is an import-graph walk from all 14 App Router
entry points, not grep.

| | Found | Fixed | Left open |
|---|---|---|---|
| Blocking / hard-rule | 6 | 5 | 1 |
| Real defects | 6 | 6 | 0 |
| Mobile-specific (second pass) | 3 | 3 | 0 |
| Documentation drift | 6 | 6 | 0 |
| **Investigated, not a bug** | 5 | — | — |

**Second pass, same day.** B2–B4 below were first held as design decisions,
because every available fix changed what was on screen. Harsh took all three —
*"fix everything"*, then *"fix the mobile layout"* — so they are now resolved,
along with three further mobile defects the follow-up pass surfaced (§C).

## Fixed in this pass

### A1 — `npm run lint` failed · hard rule ✅

Six `react-hooks/refs` errors in `staggered-menu.tsx`: `ref={refs.xRef}` reads a
ref bag during render. Destructured to bare identifiers once, above the JSX. A
rename — the same `RefObject`s reach the same elements.

Definition-of-done item 1 was failing, which means **every "done" claim made
before today was unverified**.

### A2 — Seventeen font families from a third-party CDN · hard rule ✅

`globals.css` opened with an `@import url("https://fonts.googleapis.com/…")`
pulling **17 families / 22 faces** — Audiowide, Playfair, Tillana, Monda, Lato
and a dozen more — render-blocking, un-subset, from a third-party origin. Three
rules broken at once: self-hosted fonts, the font budget, zero third-party.

The design uses **four** faces. Three (Onest, Outfit, Jost) were already
self-hosted via `next/font`. Only **Geist Mono** came from the CDN, so it moved
to `next/font/google` with the same weights (400/500).

**Cross-origin requests: 17 → 0.** Rendering is unchanged — same families.

### A3 — Hero light images, 1.9 MB for three files · hard rule ✅

`light_1.png` alone was **1,455 KB** (1463×1462 RGBA) against a <200KB rule.

Converted to WebP. `light_2` is lossless and byte-identical. `light_1`/`light_3`
use q=100 — chosen on measurement, not vibes: against the alpha-premultiplied
original the max per-channel error is **5–6/255** and the mean **0.4/255**,
which is invisible through the `overlay` / `plus-lighter` blends these are
composited with. Lossless was tried first and left `light_1` at 1,019 KB, still
5× over budget.

**1,937 KB → 230 KB (−88%)**, all three now under the 200KB ceiling.

### A4 — 32 unreachable files, 5,473 lines · cleanup ✅

28% of `src/` was dead. Full inventory and reasoning in
[[brain#D19 — The dead-code cull (2026-08-22)|brain D19]]. Plus **23.6 MB** of
orphaned `public/` assets; `public/` went 26 MB → 2.6 MB.

Included two conflicting Tailwind `@theme` blocks, both imported, both
redefining `--font-sans` and all twelve breakpoints, with the *dead* one winning
on import order.

### A5 — The header was rendering in the system font · defect ✅

`staggered-menu.css` asked for `var(--font-display)` and `var(--font-sans)`.
Neither exists as a custom property: they are declared inside `@theme inline`,
and `inline` means Tailwind substitutes them into generated utilities rather
than emitting them. So all four declarations were invalid at computed-value
time and the header silently inherited the preflight system stack instead of
the display face it asks for.

Repointed at the `next/font` variables, which are real properties on `<body>`.

⚠️ **This one is visible.** The logo, "let's talk" and "Menu" now render in
Outfit rather than `-apple-system`. It is a fix, not a restyle — the CSS always
asked for the display face — but it is a pixel change; revert the four lines if
the fallback was wanted.

**The trap generalises:** hand-written CSS cannot reach any `@theme inline`
token. Prefer a utility class in JSX; if you must use `var()`, name the
`next/font` variable.

### A6 — Mobile: the scroll cue sat on top of the body copy · defect ✅

At 390×844 the cue overlapped the positioning paragraph.

Not an arbitrary offset — the cue was absolutely positioned at
`bottom-[6.5rem]`, which clears the bottom row on desktop where it is
`flex-row` and one line tall. On mobile that row becomes `flex-col`, grows to
~200 px, and swallows the cue.

The cue is now the first item of the mobile column and can never collide however
the paragraph wraps. From `md` up it returns to `absolute` at the same
`bottom-[7rem]`, so **desktop is byte-identical** — verified by screenshot.

### A7 — Logo shipped as a 1254×1254 JPEG into a 36 px slot · defect ✅

31 KB of JPEG, ~34× more pixels than the slot can show, and no intrinsic size,
so the header row shifted on decode.

Now a 72 px WebP (**30.8 KB → 0.9 KB**) with `width`/`height` declared. Same
crop — the mark is unchanged on screen. `logo.jpeg` stays on disk because
`icon.tsx` / `apple-icon.tsx` still generate favicons from it at build time.

### A8 — `aria-modal` on a `complementary` role · accessibility ✅

The menu panel implements a real focus trap and scroll lock, but was a bare
`<aside>`, whose implicit `complementary` role ignores `aria-modal` — so none of
that behaviour was exposed to assistive tech. Added `role="dialog"` and an
`aria-label` (an unnamed dialog announces as just "dialog").

### A9 — `@react-three/fiber` installed, imported nowhere ✅

Zero imports across 136 files, and on the project's own rejected list. Removed.
No bundle change — it was already tree-shaken — so this is hygiene, not a win.

## Resolved on the second pass

### B2 — `/work` cropped client logos off ✅

Deck captures are 1.75:1–2.03:1; the tile was `aspect-[4/3]` with `object-cover`,
so cover filled the height and clipped **~12% off each side** — precisely where a
website screenshot keeps its logo and hero headline. "Abbott" rendered as "ott",
"DEPENDABLE HEALTHCARE" as "ENDABLE HEALTHCARE".

Now **`aspect-[16/9]` with `object-contain`** on the section's own `--cream`
ground. 16/9 sits inside the source cluster, so the letterbox is ≤6% and usually
1–2%, and **nothing is ever cropped**. Applied to both `WorkGrid` and
`WorkCarouselFallback` so the two stay consistent. `loading="lazy"` and
`decoding="async"` added while there.

### B3 — Mobile header wrapped to two lines ✅

Measured at 375px: logo + pill + toggle need **399px**, so with everything set to
wrap, what wrapped was the layout — the wordmark and the pill each broke to two
lines and the header grew to 56px.

**"let's talk" is now hidden below `md`**, and `.sm-logo` gets `white-space:
nowrap`. The pill yields because it is the only one of the three duplicated
elsewhere: Contact sits in the menu the toggle opens, and the hero carries "start
a project →". The row drops to ~281px — comfortable, not merely fitting.

### B4 — The home hero was invisible without JavaScript ✅

Two separate causes, and fixing only the first would have achieved nothing:

1. `RevealText` / `RevealItem` mounted their springs from first paint at
   `opacity: 0`. The `mounted` guard `FlowReveal` and `FooterReveal` already used
   is now extended to both, so children render plainly until hydration.
2. **`ScrollFade` seeded its spring at a flat `opacity: 0`** regardless of its
   own `appear` window — so all four act wrappers, *including* the hero whose
   `appear={[0, 0]}` means "on from the beginning", were server-rendered
   `opacity:0;visibility:hidden`. It now seeds from `opacityAt(0, …)`: the same
   window maths, asked for the position the page actually loads at. That
   resolves to 1 for the hero and 0 for the later acts — which is also the
   correct no-JS composition, since showing all four would stack them.

**186 → 6 hidden nodes.** The remaining six are three decorative light flares and
the three not-yet-on acts. Verified against the production HTML: the headline,
both CTAs, the services list and the positioning paragraph all ship visible.

This also removed a real bug for everyone: the hero overlay used to pop in a
frame late on every load, because the correct opacity only arrived on the first
rAF.

## C. Mobile pass — found after B2–B4 landed

### C1 — Touch targets far below minimum ✅

Measured at 375px, and the worst offender was the one that matters most:

| Control | Was | Now |
|---|---|---|
| Menu toggle — the *only* way to navigate on mobile | 85×**20** | 85×**48** |
| Menu panel items | 35px | 48px |
| Hero CTAs ("start a project", "see the work") | **18px** | 44px |
| Hero services links | 18px | 24px |

Nothing sits below the **WCAG 2.2 AA floor of 24px (2.5.8)** now, and the primary
controls clear the 44px AAA target.

⚠️ The services links deliberately stop at 24, not 44. At 44 each, that block
grew ~80px, floated up over the beans and read as a loose list rather than a
typographic stack — the fix was worse than the defect. 24px clears AA, roughly
fills the existing line pitch, and costs the composition nothing.

### C2 — The fixed header collided with page content ✅

The header floats over everything with no ground of its own. On the home hero
that is the design. Everywhere else it was a collision: on mobile the footer
wordmark and tagline ran straight through "Coffee Digital" and "Menu"; on
desktop the needs headline ran under the logo.

`--overlay-scrim` and `--blur-overlay-header` had been defined in the token layer
**for exactly this and applied to nothing.** They now drive a `.sm-header-scrim`
that fades in past 40px of scroll — transparent where the design wants it,
legible everywhere else.

Two traps paid for on the way:

- `--blur-overlay-header` lives in `@theme inline`, so hand-written CSS cannot
  read it (the same trap as [[#A5 — The header was rendering in the system font · defect ✅|A5]]).
  The real value now lives in `tokens.css` as `--blur-header`, and the theme
  token aliases it — one definition, reachable both ways.
- Written `backdrop-filter` before `-webkit-backdrop-filter`, the CSS minifier
  **collapsed the pair to the `-webkit-` line alone** and the blur silently
  vanished. Prefixed first, unprefixed last.

### C3 — The scrim hid the wordmark ✅

Caught in verification, not shipped: an absolutely-positioned element paints
above its *static* siblings, so at `z-index: auto` the scrim covered the logo
link and the header read as just "Menu +". `z-index: -1` puts it between the
header's transparent background and its content; the header owns a stacking
context (`position: absolute; z-index: 20`), so it cannot escape behind the page.

## Still open — needs a decision, not a patch

### B1 — Per-route JS — ✅ largely addressed, remainder is the S9 decision

**First, a correction to my own numbers.** The 242.4 / 313.1 / 474.5 KB figures
reported earlier include a ~38.6 KB `core-js` chunk that Next emits with
`noModule` — **every browser this site targets skips it**. Counting it
overstated every route equally. Measured correctly, the stub pages were 203.8 KB,
not 242.

| Route | Before (modern) | After | Ceiling |
|---|---|---|---|
| `/` | 436.1 KB | 435.4 KB | 445 KB |
| `/work` | 274.5 KB | **254.4 KB** | 265 KB |
| `/services`, `/about`, `/contact` | 203.8 KB | **183.7 KB** | 195 KB |

**What was wrong:** the global footer's entrance reveal ran on
`@react-spring/web`, and `ReducedMotion` (root layout) imported it too. Between
them, ~50 KB of spring runtime shipped to four routes that use a spring for
nothing else. The footer reveal is now a CSS transition + IntersectionObserver
and `ReducedMotion` moved to `HomeView` — reasoning, tradeoffs and two bugs the
rewrite fixed are in
[[brain#D20 — The footer reveal leaves the spring runtime (2026-08-22)|D20]].

three.js was already correctly route-split and never loaded on `/services`.

**What remains, and why it stopped here.** `/services` is now ~138 KB of
irreducible React + react-dom + App Router runtime, plus **GSAP 29.8 KB**, Lenis
7 KB, Zustand 9 KB. GSAP is the largest addressable item left and has exactly one
consumer — the staggered menu — but that is a 267-line GSAP-idiomatic timeline
driving the site's primary navigation. Porting it is a rewrite with real
regression risk, and it *is* the [[TBD#S9|S9]] runtime decision rather than a
bundle tweak. Deliberately left for that call.

### B5 — Two animation runtimes ⚠️

react-spring drives 12 files; GSAP is down to **one** import (the staggered
menu). "One animation system, not two" is violated, and in the opposite
direction from the one the docs assume. Finish the migration or restate the
rule — tracked as [[TBD#S9|S9]].

### B6 — Scene colours are duplicated, not tokenised 📋

`scene.config.ts` and `work-carousel/gl/config.ts` hardcode `#fffaf3`,
`#fff2db`, `#3f2210`, `#ffe5bf`, `#ff6a00` — the palette values, retyped.
Unavoidable in the sense that WebGL cannot read a CSS custom property, but there
is no single source of truth, so a palette change silently desynchronises the
DOM from the canvas. Read them once from `getComputedStyle` at scene init, or
generate both from one module.

The palette itself is **clean**: the dead brown trio appears nowhere in `src/`
except one comment explaining its retirement.

## Investigated, and *not* a bug

Recorded so the next audit does not re-open them.

- **Carousel cards showing a checkerboard.** That is the Bayer **dither reveal**
  resolving as a card approaches focus — the intended effect. Verified by
  advancing scroll and watching them resolve. No textures 404.
- **Work images fetched twice.** Two resource-timing entries, but the second has
  `transferSize` 0.3 KB against 181 KB decoded — a **cache hit**. One download,
  two decodes. The `<img>` fallback that causes it is the no-JS/reduced-motion
  path and is worth keeping.
- **The dark disc over "Menu".** The **Next.js dev-tools badge** (`NEXTJS-PORTAL`),
  not site chrome. Absent in production.
- **The hero headline rendering two words at once.** Caught in one early
  screenshot; the clip box measures correct (`overflow:hidden`, 40 px, exactly
  one word inside) on a settled page. A transient font-swap state, and a
  symptom of A2 rather than a layout bug — 22 faces were swapping in.
- **The same overlap reappearing after the reveal guards landed.** It looked
  like the `mounted` guard had introduced a pre-hydration layout of its own.
  It had not: the same page served from `next build` + `next start` renders one
  word, every time. Turbopack's dev server injects CSS through JavaScript, so
  there is a brief unstyled window in dev that does not exist in production,
  where the stylesheet is a render-blocking `<link>`.
  **Judge any flash-of-unstyled-content against a production build** — the dev
  server will invent ones that do not ship, and chasing those wastes a pass.

## What the audit says about the process

Three of the six blocking findings — the failing lint, the CDN fonts, the 1.4 MB
PNG — are things a green `npm run lint && npm run build` was supposed to catch,
and the definition of done claims all twelve gates were passing. **They were not
being run.** The dead code and the doc drift both grew the same way: no single
step verified the repo against its own rules.

The cheap durable fix is to make the gates automatic rather than remembered —
lint and typecheck in CI, per-route bundle sizes asserted against the ceilings
in [[CLAUDE#Performance rules|CLAUDE.md]], and a cross-origin request count of 0
asserted in the browser test. Until then this document dates fast.
