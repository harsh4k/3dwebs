# Home — Build Phases

Implementation plan for [[home]]. Upstream: [[../PRD|PRD]] · [[../Design|Design]] · [[../architecture|architecture]] · [[../brand/brand-audit|brand-audit]]

Seven phases. Each is independently shippable and independently reviewable. Phase 0 produces no pixels; phases 1–6 each end with `design-critic` → `code-reviewer` → `qa-verifier`.

**Motion weighting** (per `design-motion-principles`): marketing/brand register → **Jakub Krehel primary** (production polish, 200–500ms), **Jhey Tompkins secondary** (what could this become), **Emil Kowalski selective** (nav and form only — the frequency gate).

---

## The interaction thesis

Every distinctive motion on this page is generated by **one of two brand objects**, never by a generic effect:

| Object | What it is | What it does in motion |
|---|---|---|
| **The stripe** | 186 individual `<rect>` nodes in one SVG | Decompresses, smears, scans, sweeps, draws |
| **The bean** | The logo's half-filled counter | Fills — as cursor, as loader, as scroll readout |

This is the anti-slop mechanism. A fade-up-on-scroll is copyable by anyone; **a 186-band barcode that decompresses out of a 1px column is not, because nobody else has the asset.** If a proposed animation could be applied to any other agency site unchanged, it is rejected.

### Rejected on sight

Marquees · gradient/aurora/beam backgrounds · glassmorphism · numbered section markers (01/02/03) · uppercase tracked eyebrows above every heading · identical card grids · hero-metric template · "Trusted by" above a logo strip · scroll-jacked full-page snapping · text that assembles letter-by-letter for no reason · anything that hides content until animated.

## Phase 0 — Foundation

**No visual output. Nothing ships. This is the load-bearing phase.**

| | |
|---|---|
| Deliverable | Next 15 App Router, TS strict, Tailwind v4, `tokens.css`, fonts, `ScrollProvider`, `useGsapContext`, `useReducedMotion` |
| Files | `src/styles/{tokens,reset,fonts,global}.css` · `src/motion/{ScrollProvider.tsx,useGsapContext.ts,useReducedMotion.ts,tokens.ts}` · `src/content/{schema,site}.ts` |
| Blocks | Everything |

### The scroll engine

One Lenis instance. One RAF. `ScrollProvider` registers GSAP plugins exactly once, drives `ScrollTrigger.update` from Lenis's RAF, disables Lenis on coarse pointers and reduced motion, and exposes the roast-ramp driver. **Nothing else in the codebase instantiates Lenis or calls `gsap.registerPlugin`.**

### The authoring contract

```tsx
useGsapContext(scopeRef, () => {
  const tl = gsap.timeline({
    scrollTrigger: { trigger: scopeRef.current, start: 'top bottom', end: 'bottom top', scrub: 0.8 },
  });
  tl.to('[data-x]', { yPercent: -14, ease: EASE.linear }, 0)
    .to('[data-y]', { yPercent:  -4, ease: EASE.linear }, 0);
});
```

Rules, enforced at review:
- `gsap.from()` not `gsap.to()` for anything revealing. The element's natural CSS state is the *end* state, so a GSAP failure leaves the page whole.
- One `ScrollTrigger` per section. Many tweens inside one timeline, not many triggers.
- `transform` / `opacity` / `filter` only.
- `will-change` set at animation start, cleared at end. Never in CSS.
- Durations and easings from `motion/tokens.ts`. Never inline — `guard-tokens.mjs` blocks it.

### Scrub differential — the weight lever

Different sections get different `scrub` values so they feel like they have different mass. Most sites use `scrub: true` everywhere and everything feels identically weightless.

| Section | scrub | Reads as |
|---|---|---|
| Hero exit | `0.4` | Responsive, light |
| Proof | `1.2` | Heavy, deliberate — the evidence has weight |
| Work | `0.8` | Floating |
| Services | `0.6` | Crisp |

### Definition of done
`npm run lint && npm run build` clean · zero TS errors · Lenis running · a throwaway test tween scrubs at 60fps · reduced-motion kills Lenis · page renders complete with JS disabled.

### MAJOR — "The Grind" (load)

The signature moment of the entire site.

```
Trigger:      Page load, after fonts settle (document.fonts.ready)
Mechanism:    The stripe begins as a 1px-wide compressed column at the
              left margin — all 186 bands stacked at x≈0, scaleX 0.001.
              On load each band travels to its final x with a staggered
              ease, so the barcode DECOMPRESSES across the viewport
              left→right, like a grinder dispensing.
Stagger:      Distance-weighted, not uniform — bands nearer the left
              settle first, far-right bands travel furthest and arrive
              last. Total spread ~420ms.
Duration:     --dur-reveal (900ms)
Easing:       --ease-out-expo
Purpose:      Introduces the stripe as the site's connective device before
              any copy is read, and does it with a gesture only this brand
              can perform. 186 real DOM nodes; not a gradient, not a mask.
Reduced:      Stripe present at full width, no travel. Fades in over 120ms.
No-JS:        Stripe is at full width in CSS. This is the default state.
```

### MAJOR — line reveal

```
Trigger:      Same load timeline, offset +200ms after the stripe starts
Mechanism:    SplitText per line, each rising from a clipped bound
Stagger:      80ms desktop / per-block on mobile (per-line is imperceptible)
Duration:     --dur-reveal
Easing:       --ease-out-expo
Purpose:      Establishes reading order
Reduced:      Fully visible, no transform
No-JS:        Visible — default CSS state
```

### MINOR — the bean completes

```
Trigger:      Final beat of the load timeline (+640ms)
Mechanism:    The two bean counters in the wordmark's "ee" ligature close
              their lower arcs from 16° below horizontal to shut — the
              logo finishes drawing itself
Duration:     --dur-slow
Easing:       --ease-out-quint
Purpose:      The mark is not decoration sitting on the page; it arrives.
              One gesture, once, never repeated. Jakub: production polish
              is the thing you notice on the second visit, not the first.
Reduced:      Arcs already closed
```

### MAJOR — scroll exit (the wordmark handoff)

```
Trigger:      Scroll, scrubbed 0.4
Mechanism:    GSAP Flip. The hero wordmark travels to the nav bar's
              position and scale as ONE continuous element — not a
              crossfade between two wordmarks. Simultaneously:
                · display lines translate up at -18%
                · paragraph at -26% (faster — parallax differential)
                · bottom stripe at -8% and scales Y 1 → 0.4
                · ground begins the roast ramp
                · progress stripe in nav begins filling
Concurrent:   6 movements on one scroll gesture
Easing:       --ease-linear (mandatory — scrubbed)
Purpose:      The nav stops feeling bolted on. The visitor never sees the
              wordmark "appear"; it was always the same object.
Cost:         Flip ~6KB gz enters the home bundle. Justified — see open Q1.
Reduced:      Nav wordmark present from load. No Flip. Hero exits by
              scroll position only, no transform.
Mobile:       No Flip. Nav wordmark static.
```

### MINOR — bean cursor

```
Trigger:      Pointer move, fine pointers only (never shipped to coarse)
Mechanism:    gsap.quickTo() — mutates one existing tween, never allocates
              per mousemove. Bean follows with ~240ms eased lag.
              Over interactive elements: scales 1 → 1.8, inverts to --heat.
Purpose:      Continuous brand presence + interactive-affordance hint
Reduced:      Not rendered
Fallback:     Purely decorative — every state it shows also exists in the DOM
```

### Reduced-motion branch
Complete and elegant: stripe full-width, all type visible, nav wordmark present, no cursor. Nothing is missing — only the travel is.

### Assets required
⚠️ **Wordmark vector** ([[../TBD#S6|TBD S6]]). Currently a 916×85 PNG crop from the deck. It is the LCP element at display scale. A raster crop will look soft and will not meet the font-bound LCP budget.

### ⛔ Blocking: the counter arithmetic

The counters are factual claims and fall under Rule 0. Three problems found in [[../brand/brand-audit|brand-audit]]:

1. **"27 client marks" is 26 unique.** Spykar appears on both deck slide 4 and slide 33. Every vault doc says 27.
2. **The three-counter split doesn't match the source.** §2 wants *international / national / brands*; slide 3 splits **International (8 lines) / Asia-Pacific (2) / India (4)**. Asia-Pacific fits neither bucket, and one "international" line is a **jury seat**, not an award.
3. **Award totals are ambiguous by 2×.** 14 printed lines · ~17 with `(×2)` expanded · 31 fully expanded · 11 distinct bodies.

**Proposed resolution — honest and defensible:**

```
11              31              26
award bodies    awards          brands
```

Each with the plain-text caption the spec already mandates. **Do not build this section until the figures are signed off.**

### MAJOR — the scrubbed count

```
Trigger:      Section pinned; counters scrub across the pin duration
Mechanism:    Digit columns translate on Y. Tabular numerals so width
              never jitters. The number climbs UNDER THE USER'S SCROLL —
              not fired once on enter.
Scrub:        1.2 — the heaviest on the page. Evidence should feel weighty.
Easing:       --ease-linear
Purpose:      Directly serves "proof over promise". A fire-and-forget
              counter asserts; a scrubbed counter is COUNTED, by the
              visitor, at their own pace. They cannot skim past the number
              without watching it accumulate.
Reduced:      Final values rendered immediately, no pin
No-JS:        Final values are the server-rendered content
Mobile:       Unpinned. Counters roll once on enter.
```

### MAJOR — the scan line

```
Trigger:      Same pin timeline, offset to the back half
Mechanism:    A 2px segment of the stripe travels left→right across the
              mark grid. Marks resolve from monochrome --ink to full
              colour AS THE LINE CROSSES THEM — not on a timer, not on a
              uniform stagger. The stripe is doing the revealing.
Duration:     Scrubbed across the pin
Easing:       --ease-linear
Purpose:      Recognition, sequenced. A visitor scanning for a familiar
              name gets one delivered every ~80ms of scroll. And the brand
              device performs the reveal, so the mechanism is ownable —
              this is not a stagger-fade grid.
Reduced:      All marks full colour, immediately
No-JS:        All marks full colour
Mobile:       Full colour on entry — no scan, no hover to reveal it
Batch:        ScrollTrigger.batch — 27 marks, never 27 trigger instances
```

### MINOR — mark hover
Desktop only. Mark lifts 2px and gains full saturation early (before the scan reaches it). `--dur-fast`, `--ease-out-quint`. Tap equivalent on touch: none needed, marks are already full colour.

### Concurrent movement count
**7** — 3 counters + scan line + grid parallax (3 row rates) + ground ramp + progress stripe.

### Assets required
⛔ **27 client logos as SVG.** Rights confirmed ([[../TBD#✅ B1|B1]]) but the files exist only as raster inside the PPTX. Needed as one inlined sprite — 27 requests is indefensible. **First check whether the PPTX embeds them as EMF/vector**; if so they can be extracted with no client involvement.

### MAJOR — differential parallax

```
Trigger:      Scroll, scrubbed 0.8
Mechanism:    One timeline, five concurrent tweens at position 0:
                · column A tiles      yPercent -14
                · column B tiles      yPercent  -4
                · tile images         scale 1.06 → 1.0
                · tile captions       yPercent -22
                · stripe divider      scaleX 0 → 1
Easing:       --ease-linear
Purpose:      Depth. Text and image travelling at different rates is what
              reads as SPACE rather than a list. Critically these are the
              SAME gesture at different rates — not five unrelated ideas.
              Six unrelated movements read as chaos and induce nausea;
              six rates of one movement read as depth.
Desktop:      Full differential
Tablet:       2-col, no parallax
Mobile:       Single column, no parallax — invisible at that width, costs frames
Reduced:      Static positions. Layout is complete without it.
```

### MAJOR — the stripe hover mask

```
Trigger:      Pointer enters a tile (desktop) / tile enters viewport (mobile)
Mechanism:    Stripe bands sweep across the image in sequence, 20ms band
              stagger, revealing a higher-contrast treatment beneath.
              DIRECTION-AWARE — the sequence originates from the edge the
              pointer actually crossed, computed from entry coordinates.
Duration:     --dur-base
Easing:       --ease-out-quint
Purpose:      The brand device doing interaction work. Signals the tile is
              interactive using Coffee Digital's own asset rather than a
              generic scale-up or overlay. Direction-awareness is the
              detail that separates polish from a canned effect (Jakub).
Reduced:      Static image at final treatment
Mobile:       Plays once on enter — hover does not exist
```

### MINOR — velocity skew

```
Trigger:      Scroll velocity, via ScrollTrigger.getVelocity()
Mechanism:    Grid skews on Y by a clamped fraction of velocity, settling
              to 0 when scrolling stops. gsap.utils.clamp + mapRange.
Range:        Max ±2.5deg. Anything more is a gimmick.
Purpose:      Makes scroll feel physical rather than positional. This is
              the difference between "the page moved" and "I moved it."
Desktop:      Active
Mobile:       Disabled — native momentum already provides this feel
Reduced:      Disabled
⚠️ Status:    NEW PATTERN. Not one of the six primitives. Arguably a
              variant of parallax; if not, needs a [[../brain|brain]] entry.
```

### MAJOR — the iris

```
Trigger:      Section top travels from viewport bottom → 25% viewport height
Mechanism:    clip-path: circle(0 → 90% at 50% 45%) on the peach panel, over
              a full-bleed --ink field. Scrubbed on the shared ticker; one
              paint-only property on one element. will-change is set while the
              radius moves and dropped the moment it is open.
Duration:     None — scrubbed
Easing:       --ease-linear (the curve is the scroll)
Purpose:      Marks the chapter boundary between the pinned scene act and the
              services chapter. Every other boundary on this site is a wipe
              (the tree wipe, the stripe); this one is an aperture, because
              what it opens onto is the range of the work. It is also the only
              place --ink appears as a ground.
Primitive:    Mask reveal
Reduced:      No clip written at all — the peach panel covers the ink field
No-JS:        Same as reduced. The clip is only ever *added*, and only from
              JavaScript, so no-JS leaves the panel unclipped by construction
```

### MAJOR — the rule draws

```
Trigger:      Each row enters viewport, once
Mechanism:    The hairline above each pillar draws scaleX 0 → 1 from the left.
Duration:     --dur-slow, 100ms row stagger
Easing:       --ease-out-quint (soft spring, via <Inview>)
Purpose:      Enforces reading order on three otherwise-equal items — the eye
              follows the drawing line.
Reduced:      Rules and labels snap to full width (react-spring skipAnimation)
No-JS:        Present at full width — see "the reveal guard" below
```

> **Deferred: the rule is not yet the stripe.** The spec called for the hairline
> to be `stripe.svg` compressed to 1px so the barcode's tones show in the rule.
> That asset does not exist in `public/` yet, so the rule ships as a plain
> `--rule` hairline. Swap when the asset lands — see [[../TBD#S8|TBD S8]].

### MINOR — label mask reveal

Each pillar label rises from a clipped bound as its rule completes. `--dur-slow`, `--ease-out-quint`, offset 100ms behind the rule. Purpose: binds the name to the line beneath it so the pair arrives as one object rather than two things animating near each other.

### MINOR — row hover

Desktop, fine pointer: the row's rule darkens `--rule` → `--ink`, the label translates 4px right, and the panel lifts 2px. `--dur-fast`. Signals the whole row is the target, not just the text.

> **Deviation:** the spec asked for the rule to thicken 1px → 2px. Height is a
> layout property, and growing a hairline inside a panel reflows everything under
> it on every frame of the transition ([[../Design#9 Motion system|Design §9]]
> rule 1). Colour carries the same signal for free.

### MINOR — CTA

`explore services →`. A persistent `--heat` hairline with an `--ink` rule wiping L→R over it on hover and on keyboard focus; the arrow translates 4px. `--dur-fast`. The heat line is the section's single `--heat` element, and it is a rule rather than type because heat measures 3.28:1 on peach — enough for a graphical object, nowhere near enough for a label string.

### The reveal guard

`<Inview>` is react-spring, and react-spring writes each reveal's `from` values as
an **inline style on the first paint** — so every panel leaves the server at
`opacity: 0`. With scripts disabled nothing would ever clear it and the chapter
would ship blank, which is exactly what "nothing may be hidden by default and
revealed only by animation" forbids. Every reveal in this section therefore
carries a `reveal-guard` class, and the section renders a `<noscript>` block whose
`!important` rule restores the rest state (a stylesheet `!important` outranks a
normal inline declaration). The reveal stays **additive**: with JS the springs
play, without it the panel is simply already there.

⚠️ The same exposure exists anywhere else `<Inview>` renders content that must
survive without JS. It does not bite the scene overlays, which sit on a WebGL
canvas that needs JS regardless.

## Phase 6 — Nav + Footer

Global chrome. Specced in [[navigation]] and [[footer]] — built here because the home page cannot ship without them.

### Nav
Direction-triggered: bar translates out on scroll-down past 120px, returns on scroll-up (*"scrolling up is the universal 'I want to go somewhere' signal"*). Gains a `--paper` backdrop and hairline once past the hero. 2px progress stripe on the top edge — **reads the roast ramp's existing CSS variable; no second scroll listener.**

Link hover: label translates up and out, duplicate rises from below, rule wipes L→R. `focus-visible` shows the identical state.

⚠️ **Emil's frequency gate applies here and only here.** Nav is high-frequency and partly keyboard-initiated. Durations stay at `--dur-fast` (240ms) and no lower-priority flourish is added. This is the one section where restraint beats expression.

### Footer
Four zones only: statement / contact / navigation / legal. Tagline mask-reveals per line; the 6px stripe scales X 0 → 1 across the very bottom edge, offset 200ms.

**Purpose:** the stripe completing at the document's end bookends the visit with the same device that opened it. The Grind opens; this closes.

## Cross-cutting — the Roast Ramp

```
Trigger:      Document scroll
Mechanism:    ONE ScrollTrigger for the entire document writing ONE CSS
              custom property on :root. --ground interpolates
              --paper → --cream → --peach. Every section reads var(--ground).
              NO SECTION PAINTS ITS OWN BACKGROUND.
Easing:       --ease-linear
Desktop:      Continuous interpolation
Tablet:       Continuous
Mobile:       Stepped per section — continuous repaint is too costly
Reduced:      Static --paper throughout
Purpose:      Chapter progress made physical. The reader feels how far
              through they are without a progress bar.
```

The nav progress stripe reads the same variable. Two consumers, one driver.

### Deviations from spec, with reasons

- **No SplitText.** Words are split in markup — the tagline is short and we control it. Saves ~7KB.
- **GSAP/ScrollTrigger/Lenis are dynamically imported.** Statically bundled they put First Load at 159 kB, over budget. Deferring them costs nothing because every section server-renders finished and every reveal is a `gsap.from()`.
- **Nav and the heat CTA use CSS transforms, not GSAP** — both are in the initial bundle, so importing the engine there would undo the saving.
- **Plain `<img>` in Work**, not `next/image`: npm skipped sharp's postinstall, and the captures are already WebP at render size.
- **The wordmark is a Jost + bean-pair composite**, not the PNG crop, which is far too soft at 100px display.
